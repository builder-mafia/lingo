# Lingo Design Direction

## 1. Product Experience

Lingo는 읽은 내용을 문제로 확인하고, 자신의 언어로 이해하게 만드는 로컬 우선 학습 도구다.

우리가 만들고 싶은 경험은 "공부를 시키는 게임"이 아니라 "생각을 명료하게 만드는 짧은 학습 세션"이다.

핵심 문장:

> 읽은 것을 내 것으로 만드는 공간

## 2. Design Concept

### Calm Thinking Lab

Lingo는 조용하지만 딱딱하지 않은 개인 지식 실험실처럼 느껴져야 한다.

- 차분하지만 지루하지 않다.
- 친근하지만 유아적이지 않다.
- 전문적이지만 무겁지 않다.
- 성취를 과장하지 않고 이해의 변화를 보여준다.

Duolingo가 매일 가볍게 들어가는 학습 게임이라면, Lingo는 하나의 주제에 집중해 생각을 정리하는 개인 학습 작업대다.

## 3. Core Experience

기본 학습 흐름:

1. 핵심 요약을 읽는다.
2. 문제를 통해 이해를 확인한다.
3. 정답과 설명을 비교한다.
4. 무엇을 이해했고 무엇을 다시 볼지 정리한다.

화면은 언제나 사용자가 현재 어느 단계에 있는지 알 수 있게 해야 한다.

## 4. Design Principles

### Content First

장식보다 요약, 질문, 답변, 해설이 먼저 보여야 한다.

### One Thought at a Time

한 화면에서는 하나의 판단이나 행동에 집중한다. 동시에 여러 문제나 많은 버튼을 노출하지 않는다.

### Calm Feedback

정답과 오답은 분명하게 전달하되 사용자를 평가하거나 압박하지 않는다.

- "틀렸습니다"보다 "이 부분을 다시 살펴보세요"처럼 다음 행동을 안내한다.
- 강한 경고음이나 과도한 진동을 사용하지 않는다.
- 정답 애니메이션은 짧고 절제되게 사용한다.

### Progress Means Understanding

풀이 개수보다 이해의 변화를 보여준다.

- 처음 접함
- 다시 볼 필요가 있음
- 이해함
- 설명할 수 있음

### Local and Personal

Lingo는 경쟁 공간이 아니라 개인적인 사고 공간이다. 랭킹, 타인과의 비교, 과도한 연속 학습 압박을 기본 경험에 넣지 않는다.

## 5. Visual Language

### Colors

- **Primary — Deep Indigo:** 집중, 사고, 신뢰를 표현한다.
- **Accent — Mint or Lime:** 정답, 진전, 새로운 인사이트에 제한적으로 사용한다.
- **Background — Warm Off-white:** 장시간 읽어도 편안한 종이 같은 배경을 만든다.
- **Error — Muted Coral:** 공격적인 빨간색 대신 수정이 필요한 상태를 부드럽게 표현한다.

초기 색상 제안:

| Token | Color | Usage |
| --- | --- | --- |
| `--color-primary` | `#4338CA` | 주요 버튼, 현재 단계 |
| `--color-accent` | `#34D399` | 정답, 완료, 인사이트 |
| `--color-background` | `#F8F7F4` | 전체 배경 |
| `--color-surface` | `#FFFFFF` | 카드와 입력 영역 |
| `--color-text` | `#1F2937` | 기본 텍스트 |
| `--color-muted` | `#6B7280` | 보조 정보 |
| `--color-error` | `#E8796F` | 오답과 오류 |

색상 값은 초기 제안이며 실제 UI를 보면서 조정한다.

### Typography

- 본문 가독성을 가장 우선한다.
- 질문은 제목보다 조금 크고 명확하게 표현한다.
- 긴 요약에는 충분한 줄 간격을 사용한다.
- 강조를 위해 굵기를 지나치게 많이 사용하지 않는다.

### Shape and Depth

- 카드는 부드러운 모서리를 사용한다.
- 그림자는 약하게 사용하고 테두리와 여백으로 구조를 구분한다.
- 버튼과 선택지는 충분한 클릭 영역을 제공한다.
- 화면 밀도를 낮게 유지한다.

### Motion

모션은 축하보다 상태 변화를 설명하는 데 사용한다.

- 선택지가 선택되는 순간
- 답안 제출 후 해설이 나타나는 순간
- 한 문제에서 다음 문제로 이동하는 순간
- 세션이 완료되는 순간

모든 애니메이션은 짧고 방해되지 않아야 한다. 사용자의 애니메이션 감소 설정을 존중한다.

## 6. Voice and Writing

Lingo는 사용자를 가르치는 교사보다 함께 생각하는 동료처럼 말한다.

권장 표현:

- "핵심 내용을 확인해 볼까요?"
- "이 부분을 다시 살펴보세요."
- "이제 자신의 말로 설명할 수 있어요."
- "답을 제출하면 해설을 볼 수 있어요."

지양하는 표현:

- "실패했습니다."
- "완벽해요!!!"
- "연속 학습 기록이 사라집니다!"
- 사용자를 조급하게 만드는 표현

## 7. Screen Direction

### Note Overview

- 노트 제목
- 핵심 요약
- 예상 소요 시간
- 문제 수
- 학습 시작 버튼

### Problem

- 현재 진행 단계
- 질문
- 답변 영역
- 제출 버튼
- 제출 후 해설

### Session Result

- 점수보다 이해 상태
- 잘 이해한 내용
- 다시 볼 내용
- 다음 행동

## 8. Accessibility

- 색상만으로 정답과 오답을 구분하지 않는다.
- 키보드만으로 모든 문제를 풀 수 있어야 한다.
- 본문과 배경의 명암 대비를 충분히 확보한다.
- 애니메이션 감소 설정을 지원한다.
- 버튼과 선택지에는 명확한 포커스 상태를 제공한다.

## 9. Things We Avoid

- 캐릭터와 보상 중심의 과도한 게임화
- 순위와 경쟁을 통한 압박
- 긴 연속 학습 기록에 대한 불안 유발
- 장식 때문에 콘텐츠가 밀리는 화면
- 너무 많은 색상과 강조
- 사용자를 평가하는 듯한 문구

## 10. Open Questions

- 이해도를 사용자가 직접 선택할 것인가?
- 문제 풀이 결과를 바탕으로 이해도를 제안할 것인가?
- 세션 완료 화면에 점수를 표시할 것인가?
- 다크 모드를 초기 버전에 포함할 것인가?
- 노트별 색상이나 아이콘을 허용할 것인가?

## 11. Document Maintenance

- 제품 정체성과 디자인 원칙은 안정적인 기준으로 관리한다.
- 색상 값과 화면 구성은 초기 제안으로 취급하고 실제 UI 검증을 거쳐 조정한다.
- 결정된 항목은 `Open Questions`에서 관련 섹션으로 옮기고 결정 이유를 함께 남긴다.
