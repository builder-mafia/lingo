# Lingo Design System

이 문서는 Lingo의 브랜드 철학을 제품의 정보 구조, 시각 언어, 상호작용, 문장으로 번역하는 기준이다. 특정 화면의 유행보다 오래 유지되는 판단 원칙을 정의한다.

## 1. Brand Foundation

Lingo는 배운 것을 모아두는 저장소이자, 안다고 느끼는 상태를 자신의 말과 새로운 상황에서 확인해보는 사고 도구다.

사용자는 지식을 소비하는 사람이 아니라 자신의 지적 탐험을 주도하는 사람이다. Lingo는 정답을 재촉하는 교사가 아니라, 답을 대신하지 않고 설명이 멈춘 지점을 정직하게 비춰주는 분석가형 사고 파트너다.

핵심 약속:

> 모아둔 지식을 다시 꺼내, 자신의 이해로 만들어간다.

Lingo의 성격은 평소에는 차분하고 냉정하다. 사용자가 행동할 때는 실패를 감당할 수 있을 만큼 대담하고 자신감 있게 반응한다. 정원과 연금술은 내부의 상상적 비유일 뿐, 화면에서 식물·마법·실험실 장식으로 직접 표현하지 않는다.

## 2. Experience Principles

### Show the work, not the philosophy

브랜드 문장을 화면에 전시하지 않는다. 실제 노트, 실제 질문, 실제 답변과 피드백이 철학을 증명해야 한다. 홈페이지는 5초 안에 다음 질문에 답한다.

> 내가 무엇을 모아두었고, 지금 무엇을 다시 생각해보면 좋은가?

### Notes deepen over time

노트는 한 번 읽고 버리는 결과물이 아니라 주제에 대한 이해가 계속 깊어지는 공간이다. 새 질문과 답변은 기존 노트에 쌓이고, 요약은 현재 이해에 맞게 갱신된다.

### Productive friction, never a locked door

먼저 자신의 말로 답하도록 권하지만 요약, 이전 답변, 참고 정보는 언제든 열어볼 수 있다. 도움을 본 행동을 실패로 취급하거나 감점하지 않는다.

### Completion is a useful pause

완료는 영구적인 숙달 판정이 아니다. 사용자가 현재의 학습 목표를 충분히 정리했다고 선택한 상태이며 언제든 다시 열 수 있다. 질문 수가 0이 되었다고 노트를 자동 완료하지 않는다.

### Offer choices, preserve agency

Lingo는 다음에 생각해볼 질문을 2–3개와 이유로 제안할 수 있지만 하나를 강요하지 않는다. 연속 학습, 점수, 순위, 벌점으로 사용자를 조종하지 않는다.

## 3. Product Structure

### Notes workspace

홈은 별도의 `Understanding Map`이나 마케팅 hero가 아닌 노트 작업공간이다.

- 상단: `노트` breadcrumb와 우측 검색
- 본문: 최근 활동 순서의 밀도 높은 노트 목록
- 목록 열: `노트 → 열린 질문 → 최근 활동 → 라벨 → 상태`
- 우측 패널: `지금 답할 수 있나요?`와 구체적인 질문 후보
- 좁은 화면: 우측 패널을 목록 위로 이동하고 보조 열을 숨긴다.

노트 행은 제목과 한 줄 요약을 중심으로 읽힌다. 행을 누르면 Note Overview로 이동하고, 상태는 행 끝의 드롭다운에서 즉시 바꾼다.

### Note Overview

정보 순서는 `요약 → 이어갈 질문 → 정리한 질문`이다. 저장한 지식을 찾아온 사용자가 먼저 현재 요약을 읽고, 이어서 아직 열려 있는 사고와 이미 정리한 과정을 확인한다.

### Question Session

한 세션에는 질문 하나만 둔다. 질문과 답변 영역이 주인공이며, 요약과 이전 답변은 기본적으로 접힌 우측 맥락 패널에서 언제든 볼 수 있다.

답변을 저장하면 시도는 즉시 끝나고 `피드백 기다리는 중` 상태가 된다. 로컬 앱이 AI를 직접 호출하거나 가짜 로딩을 보여주지 않는다. 외부 AI 스킬이 나중에 피드백을 기록하면 홈에서 다시 확인할 수 있다.

### Question lifecycle

MVP에서는 질문마다 현재 답변 하나와 현재 피드백 하나를 둔다. 다시 답하면 이전 답변은 참고할 수 있지만 새 답변이 현재 답변을 대체하고, 기존 피드백은 무효화되어 새 평가를 기다린다.

사용자는 피드백을 확인한 뒤 `다시 답하기` 또는 `이 질문은 여기까지`를 선택한다. 후자를 선택해야 질문이 현재 시점에서 정리된다.

답변을 제출하면 같은 노트의 다음 미응답 질문으로 이동할 수 있다. 이동은 현재 질문을 자동으로 정리하지 않으며, 남은 질문이 없으면 노트로 돌아간다.

### Note status

상태는 이해도 점수가 아니라 작업 흐름이다.

| 상태 | 의미 | 변경 규칙 |
| --- | --- | --- |
| 시작 전 | 아직 답변 활동을 시작하지 않음 | 새 노트의 기본 상태 |
| 진행 중 | 현재 탐색하고 있음 | 첫 답변 저장 시 자동 전환 가능 |
| 완료 | 현재 학습 목표를 정리함 | 사용자만 선택, 다시 열 수 있음 |
| 나중에 하기 | 지금의 주의에서 잠시 제외함 | 사용자만 선택 |

완료 또는 나중에 하기 상태의 노트는 우측 질문 후보에서 제외한다. 열린 질문이 있는 노트를 완료할 때는 사실을 알리되 선택을 막지 않는다.

## 4. Visual Concept: Quiet Precision

Lingo는 절제된 현대적 도구처럼 보여야 한다. 화면의 평온함은 넓은 빈 공간이 아니라 예측 가능한 정렬, 낮은 대비의 표면, 정확한 글자 위계에서 나온다. 설렘은 장식이 아니라 사용자가 답을 쓰고 상태를 바꾸는 순간의 선명한 반응으로 만든다.

Linear에서는 밀도 높은 목록, 미세한 행 선택, 낮은 대비의 컨트롤, 문맥형 우측 패널 구조만 참고한다. 프로젝트 관리 지표, 진행률, Health 개념, 다크 전용 외형은 가져오지 않는다.

Framer의 디자인 시스템에서는 단일 강조색, 명도에 의한 위계, 제한된 글자 굵기, 일관된 토큰을 참고한다. 큰 마케팅 타이포그래피, 그라디언트, 포스터형 구도는 Lingo의 제품 화면에 맞지 않는다.

Material의 색상 시스템에서는 색을 고립된 hex 값이 아닌 `surface/on-surface`, `accent/on-accent`처럼 대비가 검증된 관계로 다룬다. 라이트·다크 테마는 같은 값을 반전하지 않고 각각 읽기 좋은 톤을 가진다.

## 5. Color System

### Brand color: Cobalt

브랜드의 핵심 색은 코발트다.

- 파랑의 낮은 각성도는 긴 읽기와 냉정한 관찰을 방해하지 않는다.
- 보라에 가까운 깊이는 단순한 업무 도구보다 지적 탐험의 여지를 남긴다.
- 충분히 선명한 중심 톤은 답변 제출, 선택, 포커스처럼 행동하는 순간에 자신감을 준다.
- 초록의 성장, 빨강의 성공·실패처럼 이미 굳어진 의미에 기대지 않아 상태를 평가로 오해하게 만들지 않는다.

색의 의미는 문화와 개인에 따라 달라질 수 있으므로 코발트만으로 상태를 전달하지 않는다. 모든 중요한 상태는 텍스트, 아이콘, 위치 또는 테두리를 함께 사용한다.

### Usage rule

코발트는 링크, 키보드 포커스, 선택 상태, 주요 행동에만 쓴다. 로고 장식, 카드 배경, 단순한 숫자 강조에 반복해서 사용하지 않는다. 화면의 대부분은 중립색이어야 하며, 그 덕분에 행동 가능한 요소가 정확히 보인다.

성공·경고·오류 색은 브랜드색이 아니라 기능색이다. 실제 시스템 상태에만 제한적으로 사용하고 `진행 중`이나 `완료`를 초록색 이해도 점수처럼 표현하지 않는다.

## 6. Typography

- 시스템 sans stack을 사용해 로컬 설치와 여러 운영체제에서 빠르고 안정적으로 읽힌다.
- 기본 본문은 `15px / 1.6`, 목록 보조 정보는 `12–13px`, 페이지 제목은 `21–29px`를 기준으로 한다. 표 헤더처럼 반복되는 가장 작은 정보도 원칙적으로 `11px` 아래로 내리지 않는다.
- 굵기는 주로 400, 500, 600만 사용한다. 위계는 과도한 굵기보다 크기와 명암으로 만든다.
- 노트 제목과 질문은 한국어에서 지나친 자간 축소를 피한다. 숫자 열은 `font-variant-numeric: tabular-nums`를 사용한다.
- 긴 요약과 답변은 읽기 폭을 약 `68ch`로 제한한다.

## 7. Spacing, Shape, and Density

- 4px 단위를 기본 리듬으로 사용한다: `4, 8, 12, 16, 24, 32, 48`.
- 데스크톱 노트 행 높이는 약 `68px`로 유지해 가독성과 한 화면의 비교 가능성을 함께 지킨다.
- 기본 모서리는 6px, 입력·팝업은 8px, 큰 패널은 최대 10px다. pill은 상태나 짧은 label처럼 의미가 있을 때만 쓴다.
- 화면 구조는 그림자보다 대비가 확보된 1px 경계, 표면 톤, 여백으로 나눈다. 그림자는 떠 있는 팝업에만 제한한다.
- 입력과 드롭다운은 hover 전에도 기본 경계를 보여 조작 가능한 영역을 분명히 한다. hover에서는 경계와 표면 대비만 한 단계 높인다.
- 클릭 가능한 작은 아이콘도 실제 hit area는 최소 36px, 주요 touch target은 44–48px를 확보한다.

## 8. Iconography

- 인터페이스 아이콘은 `lucide-react`에서 의미가 가장 가까운 아이콘을 선택한다.
- Unicode 기호, emoji, 화면마다 새로 그린 SVG를 아이콘 대신 사용하지 않는다. 브랜드 마크와 단순한 CSS 상태 표시는 예외다.
- 기본 크기는 `16px`, 기본 `stroke-width`는 `2`를 기준으로 하며 텍스트와 함께 쓰는 아이콘은 고정된 정사각형 wrapper 안에서 중앙 정렬한다.
- 장식이 아닌 아이콘은 텍스트 레이블 또는 접근 가능한 이름과 함께 사용한다. 색만으로 의미를 전달하지 않는다.

## 9. Interaction and Motion

- 검색, 필터, 목록 선택처럼 반복되는 조작은 즉시 반응하며 애니메이션하지 않는다.
- 버튼은 눌렀을 때 `scale(0.98)` 정도의 짧은 피드백만 사용한다.
- 팝업은 trigger 기점의 transform origin을 사용하며 120–160ms 안에 끝난다.
- `transition: all`을 금지하고 변화하는 속성만 지정한다.
- hover 스타일은 hover 가능한 fine pointer에서만 적용한다.
- hover는 `surface-hover`, 눌림·열림·현재 선택은 코발트가 섞인 `surface-active`를 사용해 상태를 눈으로 구분한다. 상태 차이를 색 하나에만 맡기지는 않는다.
- `prefers-reduced-motion: reduce`에서는 기능에 필요하지 않은 모션을 제거한다.
- 저장·피드백 대기처럼 중요한 변화는 애니메이션보다 문장과 상태 레이블로 설명한다.

## 10. Voice and Feedback

Lingo는 분석가형 사고 파트너처럼 짧고 구체적으로 말한다. 사용자의 능력이나 성격을 평가하지 않고 현재 답변에서 관찰되는 사실을 말한다.

피드백 구조:

1. `분명하게 설명한 점`
2. `설명이 멈춘 지점`
3. `다음에 생각해볼 질문`

실제 후속 질문으로 답할 가치가 있다면 피드백 문자열에 묻어두지 않고 새 Question으로 만든다.

권장:

- `이 답변에서는 캐시 무효화가 필요한 이유를 구체적으로 설명했어요.`
- `동시 요청이 들어올 때 어떤 값이 남는지는 아직 설명되지 않았어요.`
- `두 요청이 같은 키를 갱신한다면 결과가 어떻게 달라질까요?`
- `피드백 기다리는 중`
- `이 질문은 여기까지`

지양:

- `빈틈 1개 발견`
- `설명 가능 · 응용 미확인`
- `아직 설명해보지 않음`
- `실패했습니다`, `완벽해요!!!`
- 사용자를 압박하는 연속 학습·마감 문구

## 11. Search and Filtering

- 검색 입력은 Notes 화면 우상단에 항상 보인다. 별도 dialog나 command palette를 만들지 않는다.
- Notes 화면에서만 `Cmd/Ctrl + F`가 앱 검색에 focus되고 전체 텍스트가 선택된다.
- Note Overview와 Question Session에서는 브라우저 기본 찾기를 보존한다.
- 검색은 제목과 요약을 현재 목록에서 즉시 좁힌다.
- 상태·라벨 필터와 정렬(`최근 활동`, `오래된 활동`, `제목`)은 URL search params로 표현해 새로고침과 링크 공유에도 유지한다.

## 12. Accessibility

- 일반 텍스트는 배경과 최소 4.5:1, 큰 텍스트와 UI 경계는 최소 3:1 대비를 목표로 한다.
- 색만으로 상태를 전달하지 않는다. 텍스트와 형태를 항상 함께 제공한다.
- 모든 목록 행, 검색, 필터, 상태 선택, 질문 답변을 키보드로 조작할 수 있어야 한다.
- 포커스 링은 배경과 구분되며 `:focus-visible`에서만 보인다.
- 확대 200%에서도 정보가 잘리거나 조작이 사라지지 않아야 한다.
- 가능한 컨트롤은 Base UI의 접근 가능한 primitive를 사용하고 실제 링크는 링크 semantics를 유지한다.

## 13. What We Avoid

- 브랜드 철학을 설명하는 hero와 슬로건 중심 화면
- 게임 캐릭터, 점수, streak, 배지, 진행률 퍼센트
- 이해를 단정하는 자동 점수와 영구적인 숙달 상태
- 초록=정답, 빨강=오답에만 의존하는 상태 표현
- 장식적 그라디언트, glow, glassmorphism, 과도한 그림자
- 모든 데이터를 카드로 분리해 비교를 방해하는 낮은 정보 밀도
- 작동하지 않는 내비게이션, 설정, command palette의 선행 구현
- 정원·연금술 비유의 직접적인 아이콘과 일러스트

## 14. Document Maintenance

- 브랜드 약속과 경험 원칙은 안정적인 기준으로 관리한다.
- 토큰 값은 라이트·다크 화면과 실제 콘텐츠를 함께 검증한 뒤 변경한다.
- 새로운 화면은 먼저 사용자의 질문, 주요 행동, 상태 전이를 정의한 뒤 시각 요소를 추가한다.
- 결정된 내용은 다시 `Open Questions`로 되돌리지 않는다. 새로운 불확실성은 별도 결정 기록에서 맥락과 함께 다룬다.
